## Problem Statement

Build a personal portfolio/homepage that serves as the digital front door from LinkedIn. Primary goal: convert a LinkedIn click into a work inquiry. Secondary goal: impress fellow developers enough to recommend you. Must be clean, modern, minimal, and technically flawless. "Works REALLY REALLY WELL" is not a vague aspiration — it's the measurable standard.

## What Makes This Cool

The X factor is craft quality, not gimmicks. The site loads in under 1 second, scores Lighthouse 100/100 on all four categories, ships < 5KB total JavaScript, has zero console errors, and makes no unnecessary network requests. A recruiter sees polish and substance. A developer opens DevTools and finds nothing wrong. The absence of flaws IS the feature.

V2 potential: "view source" portfolio mechanic where sections reveal their implementation code, making the site itself the case study.

## Constraints

- No blog
- No game room or heavy interactive features
- "Less is more" — animations must be restrained, classy, minimal
- No CMS — content lives in Markdown + JSON, edited directly
- Contact form is V2, not V1
- Must work on specified browser matrix (see below)
- Dark mode required (default, with light mode toggle)

## Approaches Considered

### Approach A: Astro Minimal — Ship This Weekend (CHOSEN)

Astro 5 + Tailwind v4 + TypeScript. No React, no Vue. Ships pure HTML/CSS by default. Interactive bits (dark mode toggle, scroll animations) as vanilla JS islands. Two core page types: home and project case studies. Content in Markdown + JSON via Astro content collections. Deploy to Vercel or Cloudflare Pages.

- **Effort:** S (1 weekend)
- **Risk:** Low
- **Pros:** Lighthouse 100 nearly free, "less is more" matches framework philosophy, View Transitions built in, type-safe content collections
- **Cons:** Vanilla JS for interactive bits means hand-rolling, retrofitting if heavy interactivity needed later

### Approach B: Next.js Lean — Full React Foundation

Next.js 15 App Router + Tailwind v4 + TypeScript. React components throughout. Static export for portfolio pages. Same content model.

- **Effort:** M (1-2 weekends)
- **Risk:** Medium
- **Pros:** Familiar React ecosystem, easy API routes for contact form later, strong image optimization
- **Cons:** Ships ~80KB React runtime for a content site, harder to hit zero-JS, over-engineered for requirements

### Approach C: View Source Portfolio — Craft as Content

Same Astro base as A, plus code-reveal mechanic on sections. Phased: V1 = A, V2 adds reveal layer.

- **Effort:** M (2-3 weekends, phased)
- **Risk:** Medium
- **Pros:** Genuinely novel, collapses both audiences into one mechanic, site itself is the portfolio piece
- **Cons:** Could feel gimmicky, adds JS for reveal components

## Recommended Approach

**Approach A (Astro Minimal)** with a clear V2 roadmap to Approach C's view-source mechanic.

### Visual Design Decisions

- **Gray scale:** Tailwind `neutral` — zero undertone, maximum accent color flexibility, anti-slop aligned. Chosen over zinc (too default/ubiquitous), slate (too blue), and stone (too warm, constrains accent choices).
- **Color tokens (dark mode — default):**
  - Background: `neutral-950` (#0a0a0a)
  - Surface (cards, code blocks): `neutral-900` (#171717)
  - Border: `neutral-800` (#262626)
  - Border hover: `emerald-400` (#34d399)
  - Body text: `neutral-300` (#d4d4d4)
  - Headings: `neutral-100` (#f5f5f5)
  - Muted text (dates, metadata): `neutral-500` (#737373)
  - Accent: `emerald-400` (#34d399) — 9.4:1 contrast on neutral-950, exceeds AAA
- **Color tokens (light mode):**
  - Background: `neutral-50` (#fafafa)
  - Surface: `white` (#ffffff)
  - Border: `neutral-200` (#e5e5e5)
  - Border hover: `emerald-700` (#047857)
  - Body text: `neutral-700` (#404040)
  - Headings: `neutral-900` (#171717)
  - Muted text: `neutral-500` (#737373)
  - Accent: `emerald-700` (#047857) — 5.9:1 contrast on neutral-50, passes AA
- **Typography:**
  - Font stack: Inter for body/headings, JetBrains Mono for code/technical accents
  - Strong hierarchy via weight and size, not color
  - Scale (using Tailwind text utilities):
    - Hero name: `text-4xl` / `font-bold` (36px)
    - Hero role: `text-xl` / `font-normal` (20px)
    - Tagline: `text-lg` / `font-normal` (18px)
    - Section headings: `text-2xl` / `font-semibold` (24px)
    - Card title: `text-lg` / `font-semibold` (18px)
    - Body text: `text-base` / `font-normal` (16px)
    - Small/meta text: `text-sm` / `font-normal` (14px)
    - Code/mono: `text-sm` / JetBrains Mono (14px)
  - Line heights: body 1.6 (`leading-relaxed`), headings 1.2 (`leading-tight`)
  - Font weight usage: `font-normal` (400) for body, `font-semibold` (600) for emphasis, `font-bold` (700) for hero name only
- **Layout:** Single column, generous whitespace, max-width ~720px for content
- **Alignment:** Left-aligned text throughout (headings, body, cards). The 720px content block is centered on the page, but all text within it is left-aligned. No centered headings, no centered body text. This is an anti-AI-slop decision.
- **Spacing scale:** Tailwind default (4px base grid). Key spacing values:
  - Section gap (between hero/bio/projects/footer): `space-y-24` (96px)
  - Card gap (between project cards): `space-y-8` (32px)
  - Card internal padding: `p-6` (24px)
  - Page horizontal padding: `px-6` (24px) on mobile, `px-0` on desktop (720px container handles it)
  - Hero vertical padding: `py-16` (64px) top, `py-12` (48px) bottom
  - Footer vertical padding: `py-12` (48px)
  - Tag gap (between tech stack tags): `gap-2` (8px)
  - Body paragraph spacing: `space-y-4` (16px)
- **Cards:** Thin borders (1px), not shadows. Border-radius: 4px (`rounded`). Hover state: border color shifts to emerald accent (0.15s ease transition). No translateY hover effect.
- **Animations:** Restrained. Fade-up on scroll for project cards via IntersectionObserver. Home page only — case study pages use no scroll animations, content loads statically. View Transitions: default crossfade between pages, header persists (no transition on nav). No animation library.
  - Fade-up: `opacity: 0 → 1`, `translateY(16px) → 0`, duration `0.4s`, easing `ease-out`
  - Card stagger: 100ms between each card (3 cards = 0ms, 100ms, 200ms delay)
  - Card border hover: `0.15s ease` transition on `border-color`
  - View Transition crossfade: browser default duration (~250ms)
  - `prefers-reduced-motion: reduce` disables all of the above (see Accessibility section)
- **Header:** Minimal sticky header on all pages. Left: site name (text, links to `/`). Right: dark mode toggle. Background: same as page background with subtle border-bottom (1px `neutral-800` dark / `neutral-200` light). No blur/frosted glass effect. Padding: `py-4 px-6`.
- **Dark mode toggle:** In the header (right side). Simple button, no icon — uses text: "Light" / "Dark" (shows the mode it will switch TO). `role="button"`, `aria-pressed`, keyboard operable.
- **CTA button:** Filled style. Dark mode: `emerald-400` bg + `neutral-950` text. Light mode: `emerald-700` bg + `white` text. Padding: `py-3 px-8`. Border-radius: 4px. Hover: slight opacity reduction (0.9). No other hover effects.
- **Tech stack tags:** Plain text, JetBrains Mono, 13px, `neutral-400` text (dark) / `neutral-500` text (light), slash-separated with `neutral-600` separator (dark) / `neutral-400` separator (light). Example: `React / TypeScript / Node.js`. No pills, no borders, no background.
- **Social links:** Text only — "GitHub", "LinkedIn", "Email" as plain links. Separated by ` · ` (middle dot). Color: `neutral-400` (dark) / `neutral-500` (light). Hover: shifts to `neutral-200` (dark) / `neutral-700` (light). No icons.
- **Anti-slop rules:** No gradients. No decorative blobs/waves/SVG dividers. No icons in colored circles. No emoji as design elements. No colored left-borders on cards. Tagline must NOT be generic ("Welcome to my portfolio", "Your all-in-one solution").
- **Accessibility:** All text/background combinations must meet WCAG AA contrast ratios (4.5:1 for body text, 3:1 for large text). Verify both dark and light themes independently. Neutral gray scale verified: `neutral-300` on `neutral-950` = 10.4:1 contrast (exceeds AAA).
- **Dark mode FOUC prevention:** Dark mode preference stored in localStorage, applied via inline `<script>` in `<head>` to prevent flash of unstyled content. Toggles a `dark` class on `<html>`. Defaults to `prefers-color-scheme` if no stored preference.

### Responsive Design

- **Breakpoints** (Tailwind defaults):
  - Mobile: 0–639px (base styles, single column, full-width cards)
  - Tablet: 640px+ (`sm:`) — no layout changes needed, 720px max-width handles it
  - Desktop: 768px+ (`md:`) — hero name scales up, more generous section spacing
  - No `lg:` or `xl:` breakpoints needed — 720px max-width means layout is identical above 768px
- **Mobile-specific layout:**
  - Hero name: `text-3xl` on mobile → `text-4xl` on `md:`
  - Section spacing: `space-y-16` (64px) on mobile → `space-y-24` (96px) on `md:`
  - Card padding: `p-4` (16px) on mobile → `p-6` (24px) on `md:`
  - Page horizontal padding: `px-6` (24px) — constant across breakpoints (container centers on desktop)
  - Project cards: always single column (720px max-width = no grid needed)
  - Case study prev/next nav: stacked vertically on mobile, inline on `sm:`
- **Touch targets:** All interactive elements (CTA buttons, links, dark mode toggle, prev/next nav) minimum 44x44px tap target (WCAG 2.5.5 AAA). Achieved via padding, not oversized text.
- **Viewport meta:** `<meta name="viewport" content="width=device-width, initial-scale=1">` — no `user-scalable=no` (allow pinch zoom)
- **Browser matrix:**
  - Chrome 120+ (desktop + Android)
  - Firefox 120+ (desktop)
  - Safari 17+ (macOS + iOS)
  - Edge 120+ (desktop)
  - View Transitions: progressive enhancement (graceful fallback = standard page nav)

### Accessibility

- **Semantic HTML:** Use `<main>`, `<header>`, `<footer>`, `<nav>`, `<article>`, `<section>` with appropriate ARIA landmarks. No `<div>` soup.
- **Heading hierarchy:** Strict `h1` → `h2` → `h3` with no skipped levels. One `h1` per page.
  - Home: `h1` = name, `h2` = "About" / "Projects", card titles = `h3`
  - Case study: `h1` = project title, `h2` = section headings within body
  - 404: `h1` = "Page not found"
- **Keyboard navigation:**
  - All interactive elements focusable via Tab in logical order
  - Focus visible: 2px outline in accent color, `outline-offset: 2px`. Never `outline: none` without replacement.
  - Dark mode toggle: operable via Enter/Space
  - Skip-to-content link: visually hidden, appears on first Tab press, jumps to `<main>`
  - Prev/next nav on case study: standard `<a>` elements, naturally keyboard accessible
- **ARIA:**
  - Dark mode toggle: `role="button"`, `aria-label="Toggle dark mode"`, `aria-pressed="true|false"`
  - Navigation: `<nav aria-label="Main navigation">` (if nav element added), `<nav aria-label="Project navigation">` for prev/next
  - External links: `aria-label` including "(opens in new tab)" for links with `target="_blank"`
  - Project cards: no ARIA needed if using semantic `<article>` + `<h3>` + `<a>`
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` disables:
  - Scroll fade-up animations on project cards (show immediately)
  - View Transition crossfade (use instant swap)
  - Any hover transitions on card borders (instant color change instead)
- **Color not sole indicator:** No information conveyed by color alone (e.g., tech stack tags use text labels, not colored dots)
- **Image alt text:** All case study images require meaningful `alt` text. Placeholder boxes (V1) use `aria-hidden="true"`.
- **Language:** `<html lang="en">` on all pages
- **Contrast verification checklist** (both themes):
  - Body text on background: must pass AA (4.5:1)
  - Heading text on background: must pass AA (4.5:1)
  - Muted text on background: must pass AA (4.5:1)
  - Accent color on background: must pass AA for text, AA for UI components (3:1)
  - Card body text on card surface: must pass AA (4.5:1)
  - Focus outline on background: must pass 3:1
